# max-bridge

Мессенджер MAX внутри Telegram. Открываете мини-апп в Telegram — и переписываетесь в MAX своим аккаунтом, не ставя отдельное приложение и не переключаясь между двумя мессенджерами.

Кому это нужно: у вас есть аккаунт MAX, потому что там сидят коллеги, школьный чат или госуслуги, но жить вы предпочитаете в Telegram. Мост держит сессию MAX на сервере и показывает её вам в привычном интерфейсе, а бот пишет в Telegram, когда в MAX приходит новое сообщение.

## Что умеет

**Переписка.** Список чатов с папками «Все / Новые / Каналы» — папки листаются свайпом. Открытый чат начинается с последних сообщений, даты разбиты по дням. Отправка текста, ответ свайпом по сообщению справа налево, редактирование, удаление (в том числе у всех), пересылка контактам. Реакции — весь набор MAX, 74 эмодзи, не шесть популярных. Стикеры. Галочки доставки: одна — доставлено, две — прочитано. Индикатор «в сети» у контактов, синие галочки у подтверждённых каналов и ботов.

**Медиа и файлы.** Фото, видео, голосовые и документы показываются в чате, а не подписью «вложение». Просмотрщик открывается на весь экран, листается, масштабируется, закрывается свайпом вниз и системной кнопкой «назад». Из просмотрщика картинку или ролик можно сохранить, документ скачивается тапом по строке. Отправлять можно фото, видео и файлы до 20 МБ.

**Каналы.** Лента постов с числом просмотров, ветки комментариев под постом, реакции на комментарии, переход в профиль автора комментария. Подписка на канал прямо из поиска и отписка из шапки.

**Поиск.** Одно поле ищет и по вашим чатам, и по всему MAX: сверху ваши, ниже — публичные каналы и боты с описанием, числом подписчиков и ссылкой. Найденный канал открывается карточкой, откуда на него можно подписаться.

**Настройки** повторяют экран MAX: профиль, папки, безопасность с чёрным списком, список устройств, вошедших в аккаунт, уведомления, оформление.

**Уведомления в Telegram.** Бот присылает уведомление о новом сообщении. Любой чат или канал глушится долгим нажатием на него в списке; заглушённые собраны в настройках, там же общий выключатель. Чат, который вы заглушили в самом MAX, бот тоже не трогает.

## Как это работает

У MAX нет публичного API. Есть веб-клиент `web.max.ru`, который держит WebSocket с сервером и говорит по нему собственным бинарным протоколом.

Мост поднимает на сервере headless-Chromium с этим клиентом, перехватывает уже авторизованный сокет и дальше общается с MAX напрямую — своими кадрами, а не кликами по интерфейсу. Так идут история, отправка, реакции, удаление, поиск, подписки, комментарии. Что разобрано — записано в [docs/max-protocol.md](docs/max-protocol.md): 33 опкода, раскладка кадра, формы вложений.

Через интерфейс браузера делается только то, для чего опкод пока не снят: отправка вложений и действия с чатом.

```
apps/web      мини-апп на React
apps/api      Fastify: сессии, маршруты, SQLite, Telegram-бот
apps/worker   Playwright: браузерная сессия MAX на пользователя
packages/*    домен, разбор протокола MAX, контракт api ↔ worker
```

API и воркер — разные процессы, между ними unix-сокет. Записи пользователей в SQLite зашифрованы, ключи подаёт systemd, в репозитории их нет.

## Что нужно для работы

**Сервер.** Linux с systemd и правом ставить Chromium. Считайте память по числу одновременно активных людей: у каждого свой браузер. Для команды в десяток человек хватает 4 ГБ, дальше линейно.

**Node.js 22 или новее.**

**Домен с HTTPS.** Telegram открывает мини-апп только по https, и API проверяет, что `MAXBRIDGE_PUBLIC_ORIGIN` — именно https и именно корень домена. В комплекте есть юнит `maxbridge-cloudflared`, если туннеля ещё нет.

**Бот в Telegram** — токен от @BotFather и ваш Telegram ID в `MAXBRIDGE_ADMIN_TELEGRAM_ID`: этот человек одобряет новых пользователей, без него API не стартует.

**Два ключа шифрования**, `master-key` и `lookup-key`, в `/etc/maxbridge/credentials/`. systemd отдаёт их процессу через `LoadCredential`, на диск приложения они не попадают.

**Аккаунт MAX и телефон под рукой.** Вход происходит внутри мини-аппа: номер, код из SMS, иногда капча. Логинится браузер на сервере, поэтому MAX видит вход с его IP — это нормально, но письмо «новый вход в профиль» вам придёт.

## Установка

```bash
git clone git@github.com:Rasteo123/max-bridge.git
cd max-bridge
npm ci
npm run verify        # lint, типы, 705 тестов, сборка
```

Релиз — tar-архив собранного дерева. Установщик распаковывает его в `/opt/maxbridge/releases/<timestamp>-<sha>`, ставит зависимости, тянет Chromium и переключает симлинк `current`:

```bash
npm run build
REL=$(date -u +%Y%m%dT%H%M%SZ)-$(git rev-parse --short=7 HEAD)
tar --exclude-vcs --exclude=node_modules -czf /tmp/maxbridge-$REL.tar.gz \
  apps packages ops package.json package-lock.json
scp /tmp/maxbridge-$REL.tar.gz root@<host>:/tmp/
ssh root@<host> "bash /opt/maxbridge/current/ops/scripts/install.sh $REL /tmp/maxbridge-$REL.tar.gz"
ssh root@<host> "systemctl restart maxbridge-workers maxbridge-api"
```

Предыдущий релиз остаётся на диске, откат — `ops/scripts/rollback.sh <release-id>`.

Настройки задаёт systemd-юнит, при необходимости переопределяются в `/etc/maxbridge/config.env`:

| Переменная | Значение по умолчанию |
|---|---|
| `MAXBRIDGE_HOST`, `MAXBRIDGE_PORT` | `127.0.0.1`, `3100` |
| `MAXBRIDGE_DATABASE` | `/var/lib/maxbridge/maxbridge.sqlite` |
| `MAXBRIDGE_WORKER_SOCKET` | `/run/maxbridge/worker.sock` |
| `MAXBRIDGE_PUBLIC_ORIGIN` | адрес мини-аппа, обязательна |
| `MAXBRIDGE_BOT_ENABLED` | `false` |
| `MAXBRIDGE_ADMIN_TELEGRAM_ID` | обязательна |

## Ограничения

Часть из них — плата за отсутствие API, часть просто ещё не сделана.

Одному активному пользователю соответствует один Chromium на сервере. Это главный потолок: масштабируется линейно и упирается в память, а не в процессор.

Отправка вложений и действия с чатом (заглушить, закрепить, очистить, удалить) кликают по интерфейсу MAX в headless-браузере. Отправка вложений опознаёт кнопки по идентификаторам иконок и не зависит от языка интерфейса. Действия с чатом всё ещё ищут пункты меню по русским подписям — если MAX отрисуется на другом языке, они молча перестанут работать.

Звонить нельзя. Прошедшие звонки видны в переписке строкой вроде «входящий звонок», но позвонить из мини-аппа не получится. Опросы, отправку контакта и геопозиции он тоже не умеет — такие вложения приходят подписью «неподдерживаемое вложение» и не ломают ленту. Голосовые сообщения слушаются, но не записываются.

Свою реакцию на посте канала MAX в истории не отдаёт: там есть счётчики, но нет пометки, что поставили именно вы. Пока показываем как есть.

Настройки приватности («Найти меня по номеру», «Видеть статус в сети», пароль для входа) и завершение чужих сессий из мини-аппа не меняются — это изменения безопасности аккаунта, и экран честно отправляет за ними в приложение MAX. Разделы «Сферум» и «Пригласить друзей» не перенесены.

Числа, на которые упрётесь раньше остальных: 20 МБ на исходящее вложение, 100 МБ на просмотр входящего, 250 заглушённых чатов, 100 сообщений в странице истории, 40 результатов поиска.

## Разработка

```bash
npm run verify     # то, что стоит прогнать перед пушем
npm test           # vitest
npm run test:e2e   # playwright
```

Схемы домена в `packages/core` строгие: лишнее поле роняет разбор. Это сделано нарочно, чтобы данные не просачивались в ответ мимо схемы. Изоляцию пользователей стережёт `tests/security/cross-user.test.ts` — он проверяет, что чат одного не достаётся другому ни через маршрут, ни через WebSocket.
